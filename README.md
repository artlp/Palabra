# Palabra

Статическое веб-приложение для изучения испанской лексики. Размещается на GitHub Pages, читает словарь из Google Sheets, поддерживает отдельный прогресс пользователей через Firebase Authentication + Cloud Firestore и работает как устанавливаемое PWA.

## Что уже реализовано

- Один общий Google Sheets-источник для всех пользователей без серверного кода и без платного API-ключа. Поддерживается обычная ссылка на таблицу с доступом «всем по ссылке», опубликованный CSV и локальный CSV-файл.
- Двусторонние карточки: испанский → русский и русский → испанский. Направление выбирается случайно, но чаще показывается более слабая сторона.
- Обязательный ввод перевода, проверка вариантов и артиклей, а также отдельные режимы для ударений, специальных символов и примерных совпадений.
- Оценки `Ещё раз / Трудно / Хорошо / Легко` и интервальный алгоритм, близкий по рабочей модели к Anki.
- Firebase Google Sign-In, email/password, восстановление пароля, отдельная ветка прогресса для каждого пользователя и защищённые общие настройки источника.
- Локальный гостевой режим. При первом входе локальный прогресс переносится в пустой аккаунт.
- Аналитика: выучено сегодня и за неделю, серия дней, точность, лёгкие/сложные слова, направления перевода, части речи, график за 30 дней.
- Адаптивный интерфейс, тёмная тема, PWA и офлайн-кэш оболочки приложения.
- GitHub Actions: тесты и автоматическая публикация на GitHub Pages.

## 1. Формат Google Sheets

Первая строка должна содержать четыре заголовка в таком порядке:

| A — Артикль | B — Испанский | C — Перевод | D — Часть речи |
|---|---|---|---|
| el | nosotros | мы (мужской род или смешанная группа) | местоимение |
| la | casa | дом | существительное |
|  | ir | идти; ехать | глагол |

Для карточек приложение читает колонки **B, C и D**: испанское слово, перевод и часть речи. Колонка A с артиклем остаётся справочной. Изменение части речи не меняет идентификатор карточки и не сбрасывает учебный прогресс.

Несколько допустимых переводов в колонке C можно разделять символами `;`, `|`, `/` или переносом строки.

1. Откройте таблицу.
2. Нажмите **Поделиться**.
3. Установите **Все, у кого есть ссылка → Читатель**.
4. Скопируйте обычную ссылку вида `https://docs.google.com/spreadsheets/d/.../edit#gid=0`.
5. Войдите под аккаунтом администратора `Arthur L` и вставьте ссылку в **Настройки → Google Sheets**.

Приложение получает только отображаемые значения. Формулы и права редактирования ему не нужны. Частную таблицу без доступа по ссылке эта версия намеренно не запрашивает: для неё потребовался бы отдельный OAuth scope Google Sheets.

### Доступ к настройкам источника

Ссылка на Google Sheets и название вкладки хранятся в общем документе Firestore:

```text
appSettings/googleSheets
```

Читать этот документ могут все посетители сайта, чтобы загрузить один и тот же словарь. Изменять его может только Firebase-пользователь с UID:

```text
uuDh6U8naZeC7hHv7U3Qex3sAtE2
```

В интерфейсе поля доступны для редактирования только этому аккаунту. Для остальных пользователей они отображаются в режиме «только чтение». Основная защита находится в `firestore.rules`, поэтому изменение JavaScript в браузере не позволяет обойти ограничение.

Локальный импорт CSV доступен любому пользователю, но действует только в текущем браузере и не меняет общий источник. Нажатие **Обновить таблицу** снова загружает общий Google Sheets-источник.

### Проверка ответов

В **Настройки → Параметры занятий** доступны независимые режимы:

- **Игнорировать специальные символы** — знаки препинания, кавычки, скобки, дефисы и другие символы не влияют на сравнение.
- **Примерное совпадение** — небольшие опечатки засчитываются в пределах выбранного допуска; пояснение в скобках можно не вводить. Например, ответ `мы` принимается для значения `мы (мужской род или смешанная группа)`.
- **Засчитывать пропущенные ударения** — ответ `como` можно принять для `cómo`.

## 2. Подключение Firebase

GitHub Pages обслуживает только статические файлы, поэтому вход и персональная синхронизация вынесены в Firebase.

### Создание проекта

1. Откройте Firebase Console и создайте проект.
2. На главной странице проекта добавьте **Web app**.
3. Скопируйте объект `firebaseConfig`.
4. Откройте [`js/config.js`](./js/config.js) и замените значения `PASTE_...`.

Пример:

```js
export const APP_CONFIG = Object.freeze({
  sheetsAdminUid: 'uuDh6U8naZeC7hHv7U3Qex3sAtE2',
  sheetsAdminName: 'Arthur L',
  firebase: {
    apiKey: 'AIza...',
    authDomain: 'my-project.firebaseapp.com',
    projectId: 'my-project',
    storageBucket: 'my-project.firebasestorage.app',
    messagingSenderId: '123456789',
    appId: '1:123456789:web:abcdef'
  }
});
```

Firebase web config и UID администратора публикуются в клиентском коде по дизайну. Они не являются секретами: права записи определяются серверными правилами Firestore.

При смене администратора UID нужно заменить одновременно в двух файлах:

- `js/config.js` — для состояния интерфейса;
- `firestore.rules` — для фактического разрешения записи.

### Authentication

В Firebase Console:

1. Откройте **Authentication → Sign-in method**.
2. Включите **Google**.
3. Включите **Email/Password**.
4. В **Authentication → Settings → Authorized domains** добавьте домен GitHub Pages: `ВАШ-ЛОГИН.github.io`.

### Firestore

1. Откройте **Firestore Database** и создайте базу в Native mode.
2. Откройте вкладку **Rules**.
3. Вставьте содержимое [`firestore.rules`](./firestore.rules) и опубликуйте.

Правила разрешают пользователю читать и менять только путь `users/{его uid}/...`. Документ `appSettings/googleSheets` открыт для чтения, но запись и удаление разрешены только UID администратора `Arthur L`. Все остальные пути запрещены.

При установленном Firebase CLI правила можно развернуть командой:

```bash
firebase login
firebase use --add
firebase deploy --only firestore:rules
```

Публикация сайта через GitHub Pages **не разворачивает правила Firestore**. После обновления проекта команду выше нужно выполнить хотя бы один раз. Иначе сайт покажет ошибку `Missing or insufficient permissions` при попытке сохранить общий источник.

## 3. Публикация на GitHub Pages

1. Создайте новый **публичный** GitHub-репозиторий. Публичность нужна, чтобы использовать GitHub Pages на бесплатном аккаунте GitHub Free.
2. Поместите в него все файлы проекта.
3. Выполните:

```bash
git init
git add .
git commit -m "Initial Palabra app"
git branch -M main
git remote add origin git@github.com:ВАШ-ЛОГИН/ИМЯ-РЕПОЗИТОРИЯ.git
git push -u origin main
```

4. После первого push откройте на GitHub **Settings → Pages**.
5. В **Build and deployment → Source** выберите **GitHub Actions**. Это обязательная одноразовая настройка: без неё шаг `Configure Pages` завершится ошибкой `Get Pages site failed` / `Not Found`.
6. Откройте **Actions**, выберите неудачный запуск и нажмите **Re-run all jobs**. Вместо повторного запуска можно сделать ещё один push в `main`.
7. Workflow `.github/workflows/deploy.yml` запустит тесты и опубликует сайт.

Если раздел **Pages** недоступен, проверьте, что у вас есть права администратора репозитория. Для бесплатного GitHub Free репозиторий должен быть публичным; в организациях публикация Pages также может быть ограничена политиками организации.

Адрес проекта будет выглядеть так:

```text
https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/
```

Каждый новый push в `main` автоматически публикует обновление.

## 4. Локальный запуск

Прямое открытие `index.html` через `file://` не подходит для ES modules и `fetch`. Запустите локальный HTTP-сервер:

```bash
npm run serve
```

Затем откройте `http://localhost:8080`.

Для Google Authentication добавьте `localhost` в Authorized domains Firebase, если он там отсутствует.

## 5. Проверки

Проект не требует установки npm-пакетов.

```bash
npm test
npm run check
```

Тесты проверяют CSV, распознавание столбцов, варианты ответов, интервалы, дневную статистику, очередь и ссылки Google Sheets.

## Как устроены интервалы

После ответа пользователь выбирает оценку:

- **Ещё раз** — карточка возвращается в текущую сессию, интервал сбрасывается.
- **Трудно** — короткий или слегка увеличенный интервал.
- **Хорошо** — стандартное увеличение через коэффициент лёгкости.
- **Легко** — более длинный интервал и повышение коэффициента лёгкости.

Слово попадает в показатель «выучено», когда успешно прошло минимум два закрепления и получило интервал не менее 3 дней. «Освоено» — после устойчивой серии с интервалом не менее 14 дней и долей успешных оценок не ниже 75%.

## Структура данных Firestore

```text
appSettings/googleSheets
  shared sheetUrl, sheetName, updatedAt, updatedBy
users/{uid}
  personal learning settings, profile metadata
users/{uid}/cardProgress/{wordId}
  interval, ease, repetitions, lapses, per-direction stats
users/{uid}/daily/{YYYY-MM-DD}
  daily aggregates for charts
users/{uid}/reviews/{reviewId}
  individual review event
```

Сами слова не копируются в Firestore: источником истины остаётся Google Sheets. Общая ссылка на источник хранится в `appSettings/googleSheets`, а в пользовательских ветках сохраняются только личные параметры занятий и прогресс. При первом входе администратора старая ссылка из его профиля автоматически переносится в общий документ, если тот ещё не создан.

## Ограничения и эксплуатация

- Google Sheets должна быть доступна для просмотра по ссылке либо опубликована как CSV.
- Право изменения источника сайта не меняет разрешения самой Google-таблицы. В Google Drive аккаунту `Arthur L` следует дать роль редактора, остальным — читателя.
- Удаление строки из таблицы скрывает слово, но его старый прогресс остаётся в Firestore; при возврате той же строки стабильный идентификатор обычно восстанавливает прогресс.
- При сильном изменении испанского слова или перевода создаётся новая карточка. Колонки A и D на идентификатор не влияют.
- Firebase Spark не требует способа оплаты и включает бесплатные квоты для Authentication и Firestore. Это не безлимитный ресурс: актуальное потребление и лимиты проверяйте в Firebase Console.
- GitHub Pages доступен бесплатно для публичного репозитория на GitHub Free; для приватного репозитория требуется подходящий платный план GitHub.
- CSV, выбранный с диска, сохраняется только в текущем браузере. Для нескольких устройств используйте Google Sheets.

## Основные файлы

- `index.html` — разметка экранов и диалогов.
- `styles.css` — адаптивный интерфейс и темы.
- `js/core.js` — алгоритм карточек, проверка ответов, CSV и аналитика.
- `js/app.js` — состояние интерфейса и пользовательские сценарии.
- `js/firebase-adapter.js` — Authentication и Firestore.
- `js/sheets.js` — Google Sheets/CSV.
- `firestore.rules` — изоляция данных пользователей.
- `.github/workflows/deploy.yml` — тестирование и GitHub Pages.
