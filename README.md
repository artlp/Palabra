# Palabra

Статическое веб-приложение для изучения испанской лексики. Интерфейс публикуется на GitHub Pages, вход и персональные данные хранятся через Firebase Authentication + Cloud Firestore, а общий словарь может обновляться администратором из Google Sheets.

## Что реализовано

- Двусторонние карточки: испанский → русский и русский → испанский.
- Независимые настройки для каждого аккаунта: дневные лимиты, допуск опечаток, ударения, специальные символы, направление и тема.
- Отдельный гостевой профиль, который не смешивается с аккаунтами.
- Интервальные повторения, история, аналитика и статистика по направлениям.
- Firebase Google Sign-In, email/password и восстановление пароля.
- Приватные настройки Google Sheets только для администратора `Arthur L`.
- Один глобальный словарь для гостей и всех аккаунтов. Он хранится в `appData/vocabulary` и не пересоздаётся при входе пользователя.
- Публичный Firestore-снимок словаря содержит только распарсенные слова и время публикации — без URL Google Sheets и названия вкладки.
- Сброс прогресса доступен только `Arthur L` и действует только на текущий аккаунт.
- PWA, тёмная тема и офлайн-кэш оболочки приложения.
- Автоматические тесты и публикация GitHub Pages через GitHub Actions.

## Безопасность и изоляция аккаунтов

### Персональные настройки и прогресс

Для вошедшего пользователя серверные данные находятся только под его Firebase UID:

```text
users/{uid}
users/{uid}/cardProgress/{wordId}
users/{uid}/daily/{YYYY-MM-DD}
users/{uid}/reviews/{reviewId}
```

`firestore.rules` разрешает пользователю читать и изменять только собственную ветку. Пользователь с другим UID и гость не могут читать или менять эти документы.

В браузере данные также разделены:

- гость хранит персональные настройки и прогресс в `localStorage` под отдельным ключом `palabra:v2:guest`;
- вошедшие аккаунты кэшируют персональные данные в `sessionStorage` под ключом с их UID;
- общий словарь кэшируется отдельно один раз под `palabra:global-vocabulary:v1`, поэтому смена аккаунта не создаёт другой словарь;
- Firebase Authentication использует session persistence, поэтому вход не сохраняется навсегда после закрытия браузерной сессии;
- при выходе кэш текущего аккаунта удаляется;
- старые версии, которые сохраняли аккаунт в `localStorage`, автоматически очищаются;
- гостевой прогресс и гостевые настройки **не переносятся** в аккаунт автоматически.

Поэтому изменение гостевых настроек, например допуска опечаток или количества новых слов, не меняет настройки реального пользователя.

### Google Sheets

Приватная конфигурация источника находится в:

```text
appSettings/googleSheets
```

Она содержит URL таблицы и название вкладки. Firestore разрешает **и чтение, и запись** этого документа только Firebase UID администратора:

```text
uuDh6U8naZeC7hHv7U3Qex3sAtE2
```

В интерфейсе блок Google Sheets также полностью скрыт от остальных пользователей. Это UI-ограничение не считается основной защитой — фактическая защита выполняется Firestore Rules.

Google Sheets не перечитывается при входе, выходе или смене аккаунта. При обычной синхронизации все пользователи, включая `Arthur L`, читают уже опубликованный общий словарь. Только когда `Arthur L` явно сохраняет/обновляет источник в закрытом админском блоке, его браузер загружает таблицу и публикует распарсенный словарь в:

```text
appData/vocabulary
  words
  publishedAt
```

Этот документ доступен на чтение всем посетителям, потому что слова нужны для карточек. Он сохраняется глобально между входами и аккаунтами. URL Google Sheets, имя вкладки и другие настройки источника туда не попадают. Обычным пользователям в настройках показывается только общее количество слов.

### Сброс прогресса

Кнопки полного сброса и сброса одной карточки показываются только `Arthur L`. В Firestore удаление документов прогресса дополнительно разрешено только если одновременно выполняются два условия:

1. UID запроса совпадает с `users/{userId}`;
2. этот UID является UID `Arthur L`.

Поэтому даже администраторский reset не может случайно удалить прогресс другого аккаунта: он работает только с текущим UID. Обычные пользователи могут добавлять свои повторения, но не удалять историю прогресса через Firestore.

## 1. Формат Google Sheets

Первая строка должна содержать четыре заголовка в таком порядке:

| A — Артикль | B — Испанский | C — Перевод | D — Часть речи |
|---|---|---|---|
| el | nosotros | мы (мужской род или смешанная группа) | местоимение |
| la | casa | дом | существительное |
|  | ir | идти; ехать | глагол |

Для карточек используются B, C и D. Строка импортируется только если заполнены **обе обязательные ячейки**: B «Испанский» и C «Перевод». Если хотя бы одна из них пустая (включая строку только из пробелов), Palabra полностью игнорирует эту строку. Артикль и часть речи могут быть пустыми. Несколько допустимых переводов в C можно разделять `;`, `|`, `/` или переносом строки.

Для текущей статической архитектуры браузер `Arthur L` должен уметь напрямую прочитать таблицу. Самый простой вариант:

1. Откройте таблицу.
2. Нажмите **Поделиться**.
3. Установите **Все, у кого есть ссылка → Читатель**.
4. Скопируйте обычную ссылку Google Sheets.
5. Войдите в Palabra под аккаунтом `Arthur L`.
6. Откройте **Настройки → Google Sheets** и нажмите **Сохранить источник и обновить общий словарь**. После этого словарь остаётся глобальным в Firestore; повторять это при каждом входе не нужно.

Важно: Palabra больше не раскрывает URL таблицы другим пользователям, но права самой таблицы всё равно контролирует Google Drive. Если таблица открыта «всем по ссылке», человек, который получит эту ссылку каким-либо другим способом, сможет открыть её напрямую. Чтобы таблица была действительно private-to-Arthur на уровне Google Drive, нужен другой вариант архитектуры — например backend/Cloud Function или Google OAuth с закрытым доступом к Sheets.

## 2. Firebase

### Конфигурация клиента

Firebase web config находится в `js/config.js`. Firebase web API key и UID администратора не являются паролями: они присутствуют в клиентском приложении по дизайну. Доступ к данным должен защищаться правилами Firestore.

При смене администратора UID нужно заменить одновременно в:

- `js/config.js` — чтобы интерфейс понимал, кому показывать админские элементы;
- `firestore.rules` — это фактическая серверная защита.

### Authentication

В Firebase Console включите:

- Google;
- Email/Password.

В **Authentication → Settings → Authorized domains** добавьте домен GitHub Pages.

### Firestore

Создайте Firestore Database в Native mode и разверните `firestore.rules`.

При установленном Firebase CLI:

```bash
firebase login
firebase use --add
firebase deploy --only firestore:rules
```

### Важный порядок обновления

При переходе со старой версии сначала разверните новые Firestore Rules, затем сайт:

```bash
firebase deploy --only firestore:rules
# затем push/deploy сайта
```

Если `appData/vocabulary` ещё не существует (например, при первом переходе со старой версии), войдите как `Arthur L` и один раз нажмите **Сохранить источник и обновить общий словарь**. После создания документа словарь сохраняется глобально и при последующих входах просто загружается из Firestore. Пока общий снимок ещё не опубликован, пользователи увидят демо-словарь.

GitHub Pages workflow **не разворачивает Firestore Rules автоматически**. Их нужно публиковать отдельно.

## 3. Структура Firestore

```text
appSettings/googleSheets
  PRIVATE: sheetUrl, sheetName, updatedAt, updatedBy
  read/write: только Arthur L

appData/vocabulary
  PUBLIC READ: words, publishedAt
  write/delete: только Arthur L

users/{uid}
  PRIVATE: персональные настройки и metadata

users/{uid}/cardProgress/{wordId}
  PRIVATE: интервалы и статистика карточки

users/{uid}/daily/{YYYY-MM-DD}
  PRIVATE: дневные агрегаты

users/{uid}/reviews/{reviewId}
  PRIVATE: отдельное событие повторения
```

Слова намеренно общие и имеют единый браузерный кэш; персональные настройки и прогресс — нет.

## 4. Проверка ответов

В **Настройки → Параметры занятий** доступны независимые режимы:

- **Игнорировать специальные символы**;
- **Примерное совпадение** и выбранный допуск опечаток;
- **Засчитывать пропущенные ударения**;
- режим направления карточек;
- дневные лимиты новых слов и повторений.

Все эти значения являются персональными для текущего профиля.

Если автоматическая проверка не приняла верный по смыслу ответ, кнопка **«Засчитать ответ»** позволяет вручную отметить его как правильный. В истории сохраняются автоматический и итоговый статусы.

## 5. Публикация на GitHub Pages

1. Создайте репозиторий и поместите туда файлы проекта.
2. В **Settings → Pages** выберите **GitHub Actions**.
3. Push в `main` запускает `.github/workflows/deploy.yml`.
4. Workflow выполняет `npm test && npm run check`, собирает статический артефакт и публикует GitHub Pages.

`firestore.rules` в Pages-артефакт не входит и должен разворачиваться через Firebase отдельно.

## 6. Локальный запуск

ES modules требуют HTTP-сервера:

```bash
npm run serve
```

Затем откройте `http://localhost:8080`. Для Google Authentication при необходимости добавьте `localhost` в Authorized domains Firebase.

## 7. Проверки

Проект не требует установки npm-пакетов для тестов:

```bash
npm test
npm run check
```

Тесты проверяют алгоритм карточек, CSV, аналитику, уникальность HTML ID, наличие статических ресурсов, разделение guest/account storage, разделение двух аккаунтов и ключевые security-инварианты Firestore/Google Sheets.

## Ограничения

- Это статическое клиентское приложение: его JavaScript, Firebase web config и admin UID можно увидеть в исходниках сайта. Они не должны использоваться как секреты.
- Настройки Google Sheets защищаются Firestore, но доступ к самой таблице определяется Google Drive.
- Один публичный словарь хранится в одном Firestore-документе; приложение ограничивает размер снимка, чтобы оставаться ниже лимита документа Firestore.
- Локальный CSV действует только в текущем профиле браузера и не меняет общий словарь.
- Удаление слова из общего словаря не удаляет автоматически исторический прогресс по этой карточке.

## Основные файлы

- `index.html` — интерфейс и диалоги.
- `styles.css` — адаптивный интерфейс и темы.
- `js/core.js` — алгоритм карточек, CSV, ответы и аналитика.
- `js/app.js` — состояние интерфейса и сценарии.
- `js/local-store.js` — изолированное локальное хранение профилей.
- `js/firebase-adapter.js` — Authentication и Firestore.
- `js/sheets.js` — чтение Google Sheets/CSV.
- `firestore.rules` — серверная изоляция и admin-only операции.
- `.github/workflows/deploy.yml` — тестирование и GitHub Pages.
